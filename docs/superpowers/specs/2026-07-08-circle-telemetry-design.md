## Назначение

Механизм измерения того, **насколько эффективно фазовый план отрабатывает** в проектах, где стоит
плагин, и превращения этих измерений в конкретные предложения по **ускорению** плагина (лучше авторить
карту кодовой базы / файловый манифест / журнал, иначе резать фазы, чинить слабые verify-гейты).

Потребитель метрик — **LLM-аналитик** (Claude по запросу владельца), а не человек-с-дашбордом. Поэтому
формат — плотный, самоописательный, машиночитаемый JSON, оптимальный для рассуждения по многим прогонам.

## Ключевые ограничения (заданы владельцем)

1. **Потребитель — LLM.** Данные читает и превращает в предложения по улучшению плагина Claude, не человек.
   Владелец сам метрики не смотрит.
2. **Данные только собственные.** Это НЕ телеметрия с чужих пользователей плагина — сбор идёт только на
   машинах владельца. Согласие/приватный транспорт третьих лиц не нужны.
3. **Мультимашинность.** Владелец работает с разных машин; метрики должны сходиться в одно место, читаемое
   LLM-аналитиком с любой машины.
4. **Ноль утечки — структурно.** Владелец прямо опасается утечки секретов проектов. В хранилище не должно
   попадать НИЧЕГО чувствительного: ни путей, ни кода, ни текста ошибок, ни логов, ни имён проектов/фаз.
   Гарантия должна быть _по построению схемы_, а не «проверили и вроде чисто». Хранилище считаем так,
   будто оно завтра станет публичным по ошибке.
5. **Портируемость и «без внешних бинарей».** Python3 только stdlib, bash 3.2 (macOS) + Linux, без jq,
   без flock, хеш/JSON через `python3`. Как и весь остальной плагин.
6. **Мягкая деградация.** Не заданы env-переменные телеметрии → фича полностью off (как `CIRCLE_NO_COMMIT`).
   Best-effort: сбой телеметрии никогда не валит цикл.

## Архитектура: «расщепление доверия»

Два источника данных с разным уровнем доверия, сливаемые в одну запись прогона под fail-closed гейтом.

- **Детерминированный скелет** — всё, что цикл и `git` вычисляют _сами_, без единого байта LLM-текста:
  длительности, `attempts`, `stop_reason`, статусы фаз, `plan_changed`, объём дифа из `git numstat`,
  покрытие манифеста. Безопасен по построению — секрет физически неоткуда взять. Закрывает большинство
  выводов даже в одиночку.
- **Опциональный самоотчёт executor'а** — только диагностическое «почему»: закрытый словарь friction-тегов
  - пара clamped-int. Единственный семантичный LLM-канал; главный (и жёстко ограниченный) вектор утечки.

```
                   ┌─────────────────────────────────────────┐
   circle-loop.sh  │ per-phase: START/END time, BEFORE/AFTER  │
     (детермин.)   │ git SHA, attempts=SAME_COUNT, H1/H2,     │──┐
                   │ PHASE_STATUS, RC                          │  │
                   └─────────────────────────────────────────┘  │
                                                                  ▼
   executor session ── stat-tag/stat-count (CLI, closed vocab) ─► staging в .circle/<план>/run-stats/
                                                                  │  (gitignored: *)
                                                                  ▼
                        circle_telemetry.py stat-build  ── fail-closed whitelist-гейт ──►
                        собирает запись из фикс-схемы, HMAC-хеши, regex-скраб-бэкстоп
                                                                  │
                                                                  ▼
                   CIRCLE_TELEMETRY_DIR/runs/<machine>-<plan>-<uuid>.json  (+ локальный git commit)
                                                                  │
                                          push: opt-in CIRCLE_TELEMETRY_PUSH=1 / крон / ручной шаг
                                                                  ▼
                   LLM-аналитик: git pull → грузит весь runs/ → «если доминирует X → предложение Y»
```

## Решения по трём развилкам (адъюдикация трёх дизайн-агентов)

1. **Главный сигнал «окупилась ли разведка» — покрытие манифеста из git-дифа, НЕ хук на имена
   инструментов.** Манифест фазы уже в её теле, пофазный коммит уже есть → пересекаем _в памяти_
   объявленные пути с `git diff --name-only`, наружу отдаём только числа (`files_off_manifest`,
   `coverage_ratio`). Пути живут и умирают в процессе. PostToolUse-хук на имена инструментов
   (`search_read_ratio`) даёт похожий сигнал, но требует инъекции settings в интерактивную сессию —
   лишняя хрупкая движущаяся часть. Оставлен как **возможный поздний тир**, не первичный; при его
   отсутствии loop.log НЕ парсим (leak-риск), деградируем молча.

2. **Push НЕ в горячем цикле.** Фоновый цикл пишет файл + локальный `git commit`, но не пушит — иначе
   обзаводится сетевым/auth режимом отказа. Push — opt-in `CIRCLE_TELEMETRY_PUSH=1` либо отдельный
   шаг/крон владельца.

3. **Канал executor'а — CLI-подкоманды, а не JSON от модели.** `stat-tag`/`stat-count` валидируют
   аргумент против хардкод-множества/диапазона _при записи_. У команд нет строкового параметра —
   свободному тексту физически некуда просочиться. Строже, чем «executor пишет JSON, мы потом фильтруем».

**Идентификаторы — HMAC, не голый хеш.** `HMAC-SHA256(CIRCLE_TELEMETRY_SALT, значение)`, соль — секрет
владельца ВНЕ телеметрия-репо, синкается один раз на все машины. Голый sha низкоэнтропийного
hostname/имени плана брутфорсится по словарю; HMAC с секретом — нет. Соль не задана → `plan_id="anon"`
(теряем кросс-машинную группировку, но не течём).

## Схема записи

Один файл на прогон: run-level шапка + массив пофазных записей.

### Run-level

| Поле               | Тип       | Источник              | Зачем                                                                 |
| ------------------ | --------- | --------------------- | --------------------------------------------------------------------- |
| `schema_version`   | enum      | const                 | не путать метрики между версиями схемы                                |
| `plugin_version`   | enum      | `plugin.json`         | A/B самого плагина: упали ли attempts/duration после релиза           |
| `machine_id`       | hash      | HMAC(salt, hostname)  | «медленно на этой машине» vs «медленный план»                         |
| `plan_id`          | hash      | HMAC(salt, plan-slug) | кластеризовать прогоны ОДНОГО плана во времени                        |
| `run_uuid`         | hash      | uuid4                 | conflict-free имя файла; дедуп                                        |
| `stop_reason`      | enum      | цикл                  | `complete\|no-progress\|hang\|crash\|error\|stuck` — где план буксует |
| `run_wall_s`       | duration  | цикл                  | базовая цена прогона — то, что уменьшаем                              |
| `sessions_total`   | count     | цикл                  | число сессий на прогон                                                |
| `phases_total`     | count     | цикл                  | знаменатель для проходимости                                          |
| `status_counts`    | count-map | цикл                  | доля blocked/skipped = слабые места плана                             |
| `has_codebase_map` | bool      | парс преамбулы        | корреляция «нет карты → выше duration/буксование»                     |

### Per-phase (массив `phases[]`)

| Поле                          | Тип      | Источник                                | Зачем                                                                                 |
| ----------------------------- | -------- | --------------------------------------- | ------------------------------------------------------------------------------------- |
| `ordinal`                     | count    | цикл (`order`)                          | «фаза на позиции N всегда дорогая» без раскрытия смысла; id/title НЕ эмитятся         |
| `attempts`                    | count    | цикл (`SAME_COUNT`)                     | >1 → не закрылась с первой сессии → резать/уточнять                                   |
| `duration_s`                  | duration | цикл (`date` вокруг `run_phase`)        | ранжирование дорогих фаз                                                              |
| `outcome`                     | enum     | цикл (RC+статус)                        | `done\|blocked\|no-change\|skipped\|crash\|error`                                     |
| `plan_changed`                | bool     | цикл (H1≠H2)                            | двигала ли сессия план                                                                |
| `committed`                   | bool     | цикл                                    | попала ли работа в историю                                                            |
| `deps_count`                  | count    | цикл (len deps)                         | высокая связность + ретраи → фазы слишком серийны                                     |
| `autonomy`                    | enum     | цикл                                    | `auto\|needs-human`                                                                   |
| `files_changed`               | count    | `git diff --name-only \| wc -l`         | объём фазы объективно; имена НЕ читаем                                                |
| `lines_changed`               | count    | `git diff --numstat` суммы              | дробить огромные / мержить крошечные                                                  |
| `manifest_declared`           | count    | парс `## Файловый манифест` тела фазы   | база оценки авторинга; счёт записей, не пути                                          |
| `files_off_manifest`          | count    | derived (пересечение множеств в памяти) | **ГЛАВНЫЙ сигнал:** правки вне манифеста = разведка вслепую → манифест неполон        |
| `manifest_declared_untouched` | count    | derived                                 | объявлено, но не тронуто = манифест зашумлён/устарел                                  |
| `coverage_ratio`              | ratio    | derived                                 | `touched∩declared / touched` — нормированное качество манифеста                       |
| `subphases_added`             | count    | цикл (Δ числа фаз)                      | executor сам дробил → планировщик недодрабатывает                                     |
| `journal_digest_bytes`        | count    | цикл (размер journal-секции среза)      | рост + `journal_stale` → дайджест раздувается/устаревает                              |
| `friction_tags[]`             | enum     | executor (`stat-tag`)                   | «почему», словарь ниже                                                                |
| `blind_searches`              | count    | executor (`stat-count`, clamp [0..99])  | сколько раз искал по всему репо — прямая мера промаха карты                           |
| `verify_gate_kind`            | enum     | executor (`stat-tag`)                   | `none\|typecheck\|test-run\|smoke-exec\|manual` — слабый гейт пропускает дефекты вниз |

**Словарь friction-тегов (закрытый, версионируется `schema_version`):**
`manifest_incomplete`, `manifest_stale`, `map_gap`, `journal_stale`, `verify_weak`, `phase_too_big`,
`dep_missing`, `blind_search`, `rework`, `preamble_insufficient`, `context_slice_insufficient`,
`full_plan_fallback`.

## Модель безопасности (структурная, не дисциплинарная)

1. **Нет канала свободного текста, дотекающего до записи.** Поля цикла — числа/булевы/enum, которые
   он посчитал сам. Канал executor'а — CLI, принимающий только `(phase_id, tag∈CLOSED_SET)` или
   `(counter∈SET, int∈range)`. Строкового параметра в сигнатуре команд нет.
2. **Запись СОБИРАЕТСЯ из фикс-схемы**, а не мержится из присланных ключей. Значение может попасть
   только в предтипизированный слот. Данные executor'а — исключительно в bool-теги / closed-enum / clamped-int.
3. **Явно НЕ в записи:** phase id/title, `obstacle`-текст (свободный!), пути, диффы, содержимое loop.log,
   имя плана/проекта. `obstacle` сворачивается в `outcome=blocked` + опциональный enum-тег.
4. **Fail-closed whitelist-гейт** в `stat-build`: каждый ключ — по whitelist с проверкой типа +
   (enum-членство | int-диапазон). Неизвестный ключ / неверный тип / enum вне словаря / int вне диапазона
   → поле дропается; аномалия в обязательном/верхнеуровневом поле → **вся запись дропается**. При этом
   безопасный детерминированный скелет собирается отдельно и от самоотчёта не зависит.
5. **Regex/charset-скраббер-бэкстоп** по сериализованному JSON: hash — только `[0-9a-f]{n}`; тег/enum —
   только `[a-z_]+`/`[A-Z_]+`; любой `/`, `@`, пробел, кавычка, длинный не-hash hex в значении → провал
   → дроп всей записи. По конструкции не должен срабатывать; чистая страховка от будущего бага гейта.
6. **Идентификаторы — HMAC на локальной соли вне репо** (см. развилки). Сырые имена не сериализуются
   нигде, включая имя файла.
7. **Изоляция источников:** stats НИКОГДА не читает `loop.log` (там возможны секреты) и не ест
   `obstacle`-текст. Staging (`run-stats/*.kv`, `*.tags`) живёт в `.circle/` под `*`-gitignore — сырьё
   executor'а не покидает машину; наружу уходит только собранный, дважды провалидированный whitelist-JSON.
8. **Числовая гигиена:** durations округляются, executor-счётчики клампятся в узкий диапазон — режет
   ковровый канал через магнитуду. Критичные числа берутся из цикла/git, не из сессии.

## Консолидация

`CIRCLE_TELEMETRY_DIR` (env) → локальный клон приватного git-репо на каждой машине. Не задан → off.
`stat-build` пишет ОДИН файл `runs/<machine_id>-<plan_id>-<run_uuid>.json` (все три компонента —
опаковые хеши/uuid) атомарно (temp+rename). Уникальный uuid на прогон = conflict-free merge с любого
числа машин без ручного разрешения. Затем локальный best-effort `git add && commit` (сбой не валит цикл).
Push вынесен из горячего цикла (см. развилку 2). Транспорт намеренно сменяем: запись самодостаточна,
репо можно заменить на rsync/синк-папку без изменения продюсера.

## Аналитический workflow (измерение → ускорение)

Аналитик (Claude) делает `git pull`, грузит `runs/*.json`, группирует по `plan_id × ordinal` поверх
прогонов и применяет каталог «если доминирует X → предложение Y»:

- Высокий `files_off_manifest` + тег `manifest_incomplete` на позиции N → «манифест этого класса фаз
  системно неполон — расширить разведку при планировании». Высокий `manifest_declared_untouched` +
  `manifest_stale` → «манифест зашумлён/устарел».
- `attempts>1` / `outcome=blocked` повторяется на позиции + `phase_too_big`/`subphases_added>0` →
  «фаза на позиции N непосильна для одной сессии — резать мельче в авторинге».
- Рост `journal_digest_bytes` без падения `duration_s` + `journal_stale` → «дайджест журнала раздувается
  и устаревает — сжимать/структурировать журнал или менять срез».
- `verify_gate_kind∈{none,typecheck}` на фазе-продюсере, а у преемника по `ordinal` тег `rework` →
  «слабый verify пропускает дефекты вниз — требовать реально исполняющий код смоук».
- `has_codebase_map=false` коррелирует с `stop_reason∈{stuck,no-progress}` → «карта обязательна».
- Срез по `plugin_version`: упали ли `attempts`/`duration_s` после релиза, менявшего авторинг → доказать
  или опровергнуть эффект изменения самого плагина.

Детерминированные поля дают **что** (медленно/застряло/откат), friction-теги — **почему** (слепой поиск
vs слабый манифест vs протухший журнал). Предложения аналитик подкрепляет детерминированными числами;
теги — подтверждающий, а не единственный сигнал.

## Затрагиваемые компоненты

- **`scripts/circle-loop.sh`** — замеры per-phase (`date` вокруг `run_phase`, `BEFORE/AFTER` SHA),
  вызов сборщика после `PHASE_STATUS`, финальный `stat-build` рядом с генерацией `summary.txt`,
  локальный commit при заданном `CIRCLE_TELEMETRY_DIR`.
- **`scripts/circle_telemetry.py`** (новый, stdlib) — подкоманды `record-phase` (детерминированный
  скелет фазы в staging), `stat-tag`/`stat-count` (валидируемый при записи канал executor'а),
  `stat-build` (сборка из фикс-схемы + fail-closed гейт + HMAC + скраббер + атомная запись файла),
  хелпер парса манифеста/преамбулы (счёт, не пути). Изоляция гейт-логики под unittest.
- **`scripts/executor-prompt.md`** — опциональный шаг: «столкнулся с трением → `stat-tag ... <tag>`
  из списка; число слепых поисков → `stat-count ... blind_searches <n>`». Только под флагом.
- **`README.md` / `CLAUDE.md`** — секция «Телеметрия»: env (`CIRCLE_TELEMETRY_DIR`, `CIRCLE_TELEMETRY_SALT`,
  `CIRCLE_TELEMETRY_PUSH`), гарантии приватности, бутстрап приватного репо + синк соли, opt-out.
- **`tests/`** — unittest на гейт: fail-closed (off-schema → дроп записи), дроп неизвестного ключа/
  не-члена enum/int вне диапазона, HMAC-стабильность и необратимость без соли, `anon` при отсутствии
  соли, conflict-free имя файла, парс манифеста → счёт без путей, скраббер режет путь/пробел/`@`.

## Env-переменные

| Env                           | Дефолт                                   | Смысл                                                              |
| ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| `CIRCLE_TELEMETRY_DIR`        | не задан → off                           | локальный клон приватного репо телеметрии                          |
| `CIRCLE_TELEMETRY_SALT`       | не задан → `plan_id/machine_id = "anon"` | секрет для HMAC идентификаторов; вне репо, синкается на все машины |
| `CIRCLE_TELEMETRY_PUSH`       | не задан → только локальный commit       | `1` → best-effort push в конце прогона                             |
| `CIRCLE_TELEMETRY_SELFREPORT` | не задан → off                           | включает опциональный шаг тегирования executor'ом                  |

## Ненужное (YAGNI, вне scope)

- Парсинг `loop.log` ради метрик — исключён (leak-риск + хрупкость).
- PostToolUse-хук на имена инструментов — отложен как возможный поздний тир, не в первой версии.
- Свободнотекстовый самоотчёт / executor-авторимый JSON — исключён по модели безопасности.
- Человеко-читаемый дашборд/агрегатор — потребитель LLM, читает сырой `runs/*.json`.
- Хранение `obstacle`-текста, путей, имён — исключено; только их структурные производные.
