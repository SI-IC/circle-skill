# Реестр разборов телеметрии circle-skill

Компактная ретроспектива: что разобрано, какие приняты решения и **почему**, что отложено и при
каком условии вернуться. Цель — принимать дальнейшие правки плагина взвешенно, не переоткрывая
уже закрытые вопросы.

**Правила ведения:** обновляй на каждом `/circle-analyze`; новая запись — сверху. Держи кратко
(тезисы, не проза). Отложенное — обязательно с условием пересмотра. Здесь только выводы и решения;
сырьё телеметрии — в `.telemetry/` (gitignored), задачи — не здесь и не в бэклоге.

## 2026-07-11 · прогон `7e4371adaa2a` · плагин 0.9.0, схема v3

**Разобрано:** 1 свежий прогон (8 фаз, complete). Удалено 7 записей v1 (плагин 0.7.x): дублированные
снимки одного прогона (нестабильный `run_uuid` до схемы v2) + нет `context_pct`/`run_wall_s` — шум,
не несут смысла.

**Находки (цифры):**
- Механика цикла здорова: `complete`, 7 done / 1 skipped, все `attempts=1` (0 баунсов), 0 hang, всё `auto`.
- `context_pct=null` по ВСЕМ фазам при `duration_s` до 3220s (~53 мин) ⇒ извлечение сломано (дрейф
  формата статус-бара), а не низкая нагрузка. Логи прогона не выжили → образца строки нет.
- `journal_digest_bytes` рос 3894 → 39528 (×10) по ходу фаз.
- `run_wall_s` 53881 (~15ч) ≫ Σ `duration_s` 10911 (~3ч) ⇒ ~12ч простой (паузы/resume, ожидаемо).

**Решения — внедрено:**
- **Б1** (`run_phase.py`): локальная самодиагностика `context_pct`. `_LogFilter` копит бар-подобные
  кадры с нераспознанным `N% |`; если бар за сессию так и не сматчился — пишет в `loop.log` строки
  `CIRCLE_CTX_UNPARSED: …` с образцом (локально, **не** в телеметрию: кадр может нести пути/ветки).
  *Почему так:* чинить `_CTX_RE` по реальной строке, а не гадать вслепую (риск ложных срабатываний).
- **Б-doc**: доки интерпретации записей (README + докстринги `circle_telemetry.py` + CLAUDE.md):
  `phases[]` = фазы, исполненные В ЭТОМ прогоне, vs `phases_total`/`status_counts` = финал всего плана
  (`len(phases)<phases_total` — норма); `null`+большой `duration_s` ⇒ сломано; простой = `run_wall−Σduration`.

**Решения — отклонено (осознанно):**
- Поля `phases_recorded` и `sessions_wall_s` в схему НЕ добавляем: выводимы из уже собираемого
  (`len(phases[])` и `Σ duration_s` / `run_wall−Σduration`). Добавлять = дублирующий раздув схемы.

**Отложено (с условием пересмотра):**
- **Починить `_CTX_RE`** по реальному `CIRCLE_CTX_UNPARSED`. *Условие:* появился прогон с образцом
  бара в `loop.log`. *Блокирует* всю ось пухлости (`context_pct`) — приоритет высокий.
- **Корзина А — сжать дайджест журнала в `phase-slice`**. *Почему отложено:* рост журнала есть, но
  доказательств пухлости нет (`context_pct` мёртв — см. выше). *Условие пересмотра:* после починки
  `_CTX_RE` есть прогоны с ненулевым `context_pct` и на поздних фазах пик >60–70%. *Как делать:*
  сжатие С СОХРАНЕНИЕМ решений/граблей журнала, НЕ обрезка last-N (иначе теряется память между фазами).
