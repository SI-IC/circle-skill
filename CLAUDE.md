# CLAUDE.md — circle-skill

Плагин Claude Code: автономное исполнение фазового плана в цикле отдельными интерактивными
сессиями. Обзор и формат плана — в `README.md`. Дизайн и план реализации — в `docs/superpowers/`.

## Архитектура (кратко)

- `commands/circle-skill.md` — препролёт (LLM): поиск плана, нормализация маркеров, риск-классификация,
  подтверждение, фоновый запуск цикла.
- `scripts/circle-loop.sh` — детерминированный цикл: выбор фазы (`circle_plan.py next`) → сборка среза
  фазы (`phase-slice` → `phase-context.md`) → сессия под PTY (`run_phase.py`) → сравнение sha256 плана →
  guard коммита → стоп/продолжение. Рабочая папка — на каждый план своя: `.circle/<имя-плана>/`; цикл
  кладёт в `.circle/` `.gitignore` с `*` (логи несут сырой вывод сессий — вне VCS). **Коммитит саму работу
  фазы САМА сессия** (последним шагом после verify/journal, см. `executor-prompt.md`), а не цикл: `git add -A
  && git commit` (`circle: phase <id> — <title>`), **хуки проекта уважаются — `--no-verify` нет нигде**. Так
  падение pre-commit хука чинит тот же агент в своём контексте, без обхода и без новой сессии. Цикл держит
  `@@COMMIT_ENABLED@@` (yes/no) в промпте и **сторожит инвариант «`done` ⇒ закоммичено»** (`commit_guard`):
  признак коммита — **сдвиг HEAD** за время сессии (а не чистота дерева: хук-форматтер может оставить
  residue уже после успешного коммита). HEAD не сдвинулся и дерево грязное → сессия не закоммитила →
  возврат в `in_progress` с obstacle (баунс), цикл переизберёт фазу, свежая сессия дочинит; непочиняемый
  случай ловит backstop `MAX_SAME` → `stuck`. Identity: если имени/почты нет НИГДЕ (ни ambient
  `GIT_AUTHOR/COMMITTER_*` env, ни `git config`), цикл дозаполняет недостающее поле
  `circle-skill@local` в окружении сессии (наследуется через PTY; настоящую identity — хоть из env, хоть из
  config, хоть частичную — не перекрываем). **Push не делается никогда** (у проекта своя логика публикации).
  Guard трогает только `done` (blocked/недоделанные откатывают себя сами). Opt-out `CIRCLE_NO_COMMIT=1`
  (или не-git-репо) → `COMMIT_ENABLED=no`: сессии сказано не коммитить, guard выключен.
- `scripts/circle_plan.py` — ядро: парсинг маркеров `<!-- circle: ... -->`, выбор фазы, статусы, CLI.
  CLI `phase-slice` собирает компактный срез плана для фазы (read-once преамбула + текст фазы + дайджест
  «## Журнал») — его читает каждая фаза на старте вместо навигации по всему плану. `journal` отдаёт только
  дайджест журнала.
- `scripts/run_phase.py` — запуск интерактивного `claude` под PTY, ожидание `.circle/<план>/result`.
  Вывод PTY чистится `_LogFilter` (снят ANSI, схлопнуты подряд идущие дубли TUI-кадров) перед записью в лог;
  `_LogFilter` заодно вытаскивает потребление контекста из статус-бара (`(\d+)%\s*\|`); если за сессию бар
  так и не распознан, а бар-подобные кадры были — пишет в лог `CIRCLE_CTX_UNPARSED: …` с образцом (локально,
  не в телеметрию) для починки регэкспа по реальной строке при дрейфе формата TUI. Раз в `--heartbeat`
  сек (по умолч. 5) main пишет в лог строку `CIRCLE_PROGRESS: контекст N% · <label>` — по ней видно, что
  сессия жива и сколько контекста съела (нет статус-бара → `контекст ?`). Метку фазы даёт цикл (`--label`).
  Два дедлайна сессии: `--idle-timeout` (адаптивный, по молчанию PTY — «ноль байт дольше idle» = завис,
  т.к. живой TUI тикает даже во время долгого тула; `0`=выкл) и `--timeout` (абсолютный потолок wall-clock
  от runaway, подкреплён жёстким SIGALRM). Оба → rc=2 (`hang`); причину пишет `CIRCLE_PHASE_END: …` в лог.
  Дефолты задаёт цикл (`CIRCLE_IDLE_TIMEOUT`/`CIRCLE_TIMEOUT`).
- `scripts/executor-prompt.md` — шаблон промпта фазы-исполнителя (@@-плейсхолдеры).
- `scripts/circle_telemetry.py` — **опциональная** телеметрия эффективности (off по умолчанию; off не меняет
  поведение цикла). Детерминированный сбор (ноль LLM-токенов): HMAC-идентификаторы, fail-closed
  whitelist-скраб, число изменённых файлов из git-дифа (пути не покидают процесс), пик потребления контекста
  на фазу (`context_pct`, схема v3 — из `--context-out` файла `run_phase`; `null` если статус-бар не распознан;
  ось, независимая от `duration_s`: время не отличает пухлую фазу от медленной, а пик контекста отличает),
  сборка одного conflict-free JSON на прогон со стабильным `run_uuid` (персистится в work-dir → снимки прогона
  склеиваются на приёмнике) и реальным `run_wall_s`; клиент `send` (urllib) шлёт его на приёмник с bearer, outbox-ledger догоняет неотправленное.
  Врезка в `circle-loop.sh`: per-phase `record-phase`, финал `build-run`+`send`, строка `телеметрия: …`.
  Конфиг — из `.env` **проекта** (`CIRCLE_TELEMETRY_URL`/`_TOKEN`/`_SALT`), активация — `/circle-skill:circle-telemetry`
  (команда делегирует в `scripts/telemetry-client.sh`; логика вынесена из inline-`bash -c` в файл, иначе
  литеральные кавычки рвали обрамление).
- `scripts/telemetry_server.py` — приёмник в контейнере-базе (systemd `circle-telemetry.service`, порт 3000,
  переживает рестарт; ставит `telemetry-server-install.sh`): bearer-auth, size-cap, повторный fail-closed
  скраб, склейка по `run_uuid` (overwrite-last: финальный снимок прогона выигрывает), store под gitignore. `scripts/telemetry_analyze.py` — учёт разобранных записей
  (`fresh`/`mark`). Токен и данные НИКОГДА в VCS (`.env`/`.telemetry/` gitignored + pre-commit guard). См. README «Телеметрия».

Только подписка, не API: фазы — настоящие интерактивные сессии под PTY, не `claude -p`.

## Правила

- **Версия поднимается при каждом push `main`.** Релизь через `./scripts/release.sh [patch|minor|major]`
  — он поднимает версию в `.claude-plugin/plugin.json` И `.claude-plugin/marketplace.json` (значения обязаны совпадать),
  коммитит, пушит ветку и ставит тег `circle-skill--vX.Y.Z`. Прямой `git push origin main` без поднятой
  версии блокируется хуком `.githooks/pre-push` (обход: `--no-verify`). После клона: `git config core.hooksPath .githooks`.
- **Тесты — stdlib `unittest`, ноль внешних зависимостей.** Прогон: `python3 -m unittest discover -s tests`.
  Меняешь поведение скрипта — добавляй/обновляй тест в том же изменении.
- **Портируемость:** macOS (bash 3.2) + Linux. Без `flock` (лок через `mkdir`), без `jq`/`shasum`-зависимостей
  (хеш и JSON — через `python3`). Не добавляй внешних бинарей.
- **Реальный end-to-end** (живая сессия) тарифицируется и делает реальные изменения — не запускать
  автономно; это ручной шаг владельца (см. «Ручной smoke» в README).
